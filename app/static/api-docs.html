API Reference

Dispatch files over HTTP

A small, predictable REST API for uploading files, minting expiring links, and sharing whole folders as one download. Every example below is wired to the host you're reading this on — copy and run them as-is.

Your base URL —

Overview

The API speaks JSON and standard multipart uploads. Authenticated calls use a Bearer API key; download links are public and act as their own credential. Paths are relative to your base URL above.

POST/files/uploadstore a file, get a link
POST/directoriescreate a shareable folder
GET/file/{slug}/rawdownload bytes
GET/d/{slug}/zipdownload a folder as .zip
DEL/directories/{id}delete a folder + contents

Authentication

Create an API key from the Files page → API Keys. Send it as a Bearer token on every authenticated request. Keys bind to the first IP that uses them — if your address changes, use Reset IP in-app. Key creation, revocation, and IP reset are deliberately app-only; they are not exposed over the API.

Header
Authorization: Bearer <your-api-key>

Upload a file

Send a multipart form. You get back a public share link and (for server-side encryption) an access key to append as ?ek=.

POST/files/upload
Request
curl -X POST /files/upload \ -H "Authorization: Bearer <key>" \ -F "file=@/path/to/report.pdf" \ -F "original_filename=report.pdf"
Form fields
FieldTypeDescription
file requiredfileThe file contents.
original_filename requiredstringName shown to downloaders.
max_usesintDeactivate the link after this many downloads.
expires_in_secondsintLink auto-expires after this many seconds.
encryption_modestringnone · server · client. See Encryption.
compressboolzstd-compress before storing (skipped for already-compressed types).
randomize_filenameboolShow a random name on the download page.
temp_daysintDelete the file this many days after upload.
delete_if_idle_daysintDelete if not downloaded within this many days.
directory_idintAttach to a folder created via /directories. The folder's encryption wins.
Response
{ "slug": "abc123", "url": "/file/abc123", "raw_url": "/file/abc123/raw", "encryption_mode": "none", "access_key": null }

Download

The link is the credential — no auth header needed. Server-encrypted files require their ?ek= access key. Range requests are supported for unencrypted files.

GET/file/{slug}/raw
Download bytes
curl -L -O "/file/abc123/raw"
Server-encrypted — pass the access key
curl -L -O "/file/abc123/raw?ek=<access-key>"
Range request
curl -L -r 0-1023 -o chunk.bin "/file/abc123/raw"

Client-encrypted (end-to-end) files stream as ciphertext; the key lives only in the link's #ek= fragment and never reaches the server. Decrypt in the browser via the in-app download page.

File metadata

Fetch details without consuming a download.

GET/file/{slug}/info
curl "/file/abc123/info"

Returns filename, size_bytes, content_type, encryption_mode, max_uses, use_count, and expires_at.

Folders

A folder bundles many files behind one link at /d/{slug}. Every file in a folder shares a single encryption key, so one ?ek= (or one #ek=) unlocks the whole bundle. Create the folder first, then upload files into it with directory_id.

POST/directoriescreate a folder
Request
curl -X POST /directories \ -H "Authorization: Bearer <key>" \ -H "Content-Type: application/json" \ -d '{"title": "Q3 assets", "encryption_mode": "server"}'
Response
{ "id": 7, "slug": "foLd3r", "url": "/d/foLd3r", "encryption_mode": "server", "access_key": "the-shared-?ek=-value" }

Then upload into it — repeat per file, reusing the returned id:

curl -X POST /files/upload \ -H "Authorization: Bearer <key>" \ -F "file=@logo.svg" -F "original_filename=logo.svg" \ -F "directory_id=7"
GET/d/{slug}/infolist folder contents
curl "/d/foLd3r/info"

Returns title, encryption_mode, file_count, total_bytes, and a files array of {slug, filename, size_bytes, content_type}.

GET/d/{slug}/zipdownload everything
curl -L -O "/d/foLd3r/zip?ek=<access-key>"

Streams a .zip of every file. Server-encrypted folders need the ?ek= key. End-to-end folders can't be zipped server-side (the server has no key) — use the folder page, which decrypts and zips in your browser.

DEL/directories/{id}delete folder + all files
curl -X DELETE /directories/7 \ -H "Authorization: Bearer <key>"

Permanently removes the folder and every file inside it. Owners can delete their own; master users can delete any.

Encryption

Three modes, chosen per file (or once per folder). They differ in who holds the key.

ModeKey locationNotes
none—Stored as-is. The link is the only secret.
server?ek= queryEncrypted at rest. The server holds the key and gates each download on the access credential you share.
client#ek= fragmentEnd-to-end. The browser encrypts before upload; the key rides in the URL fragment and never reaches the server.

The #ek= fragment is never sent in an HTTP request, so end-to-end keys are unrecoverable if lost — save the full link at creation time.

Errors

Standard HTTP status codes; the body is { "detail": "…" }.

StatusMeaning
400Malformed request — bad mode, missing required field.
401Missing/invalid API key, or a missing/wrong ?ek= on an encrypted download.
403Authenticated, but not permitted (e.g. another user's file).
404Unknown slug, or a link that expired / was used up / deactivated.
413File exceeds your max size or would blow your quota.
